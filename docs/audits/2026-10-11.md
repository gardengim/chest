# Weekend audit — October 11, 2026

Scope: frontend lifecycle/DOM costs, bundled assets, native build configuration,
shared cards, and pixel styling. Preserve current launcher behavior and the agreed
content layout: category tabs, nested panel, Add inside left, layout controls right.

## Findings, fixes and sequence

1. **Repeated license payload and hidden DOM.** The bundled notices repeat entire
   license texts; About mounts the text of every closed disclosure. Deduplicate
   exact texts without removing copyright notices, lazily mount opened texts, and
   load About and its standard-license fallback only when requested.
2. **Backdrops keep unnecessary work alive.** Each library card independently
   fetches screenshots, listens for focus and creates a rotation timer; all slides
   are mounted. Gate card requests on intersection, share lifecycle observers,
   pause offscreen/hidden/reduced-motion rotation, and mount only the current and
   fading slide. Preserve stale-response protection and focus refresh behavior.
3. **Scroll, log and lookup hot paths.** Scroll handlers read geometry on every event;
   bursts of game logs copy a 2,000-line buffer for every line. Coalesce geometry
   work per animation frame and batch bounded log updates. Replace repeated
   library/group scans with derived lookup maps, preserve library order, and
   reuse the current locale’s Intl formatters. Delete removed-instance UI buffers
   and cap/expire the instance-news cache; stale failures cannot evict a retry. News workers stop scheduling additional
   instance requests when the page is left, while the four in-flight calls may
   finish and populate the shared cache.
4. **Styling drift and obsolete CSS.** Shared cards retain earlier page-specific
   geometry, duplicated bevels and obsolete Actions/creation-row styling. Remove
   superseded rules; centralize border, divider, raised/inset bevel, shadow and
   corner-step tokens. Apply these to controls, cards, panels, dialogs, nested
   panels, menus and scrollbars. Keep semantic status colors and thin separators.
5. **Native distribution configuration.** Both manifests request every Tokio
   feature; release settings do not explicitly optimize for size. Select features
   actually used and enable size optimization, thin LTO and symbol stripping.
   Retain panic unwinding and security/path validation.
6. **Verification and measurements.** Add targeted lifecycle/payload/styling
   regression checks, run full browser and Rust validation, measure web assets
   and release executable, and record practical limitations.

## Measurement boundaries

Browser fixtures can verify requests, DOM bounds, timers and interaction budgets.
They do not establish packaged WebView CPU/RSS, battery usage, Windows/Linux
behavior, or a one-hour idle profile. Report executable size only after building
it; do not extrapolate installer size or claim CPU/RSS savings without measurement.

## Shared styling contract

- `--pixel`: one design pixel; `--stroke`: two pixels; `--divider`: one pixel.
- `--corner-step` and `--corner`: two/four pixel staircase geometry; no smooth
  radius for framed controls. Size these through tokens, not per-page px values.
- `--bevel-raised` / `--bevel-inset` / `--bevel-pressed`: shared white/black alpha
  highlights and shadows. Light inventory panels use `--bevel-inventory` for
  contrast with the same geometry. Status colors remain semantic accents.
- Cards share one shell, one edge overlay and one drop shadow. Nested panels,
  dialogs and menus reuse the same border/bevel vocabulary; overlays use the
  shared deeper shadow token. Tabs retain their open edge and selected join.
- Spacing, artwork dimensions and typography are layout values, not bevel scale.
  Thin row separators intentionally use `--divider`, not the frame stroke.

## Results (local macOS Apple Silicon)

Initial measurements before this audit and final measurements are recorded below.
Release binary means the executable, not a signed installer or total .app bundle.

| Item | Before | After | Reduction |
| --- | ---: | ---: | ---: |
| License payload | 5,134,892 bytes | 1,292,535 bytes | 74.8% |
| Main JS (uncompressed) | 282,130 bytes | 224,272 bytes | 20.5% |
| Global CSS source | 42,589 bytes | 40,981 bytes | 3.8% |
| Release executable | 18,657,152 bytes | 11,689,600 bytes | 37.3% |

License entry count remains 620. Exact deduplication shares 1,002 text entries via
338 distinct texts; package-specific copyright lines remain intact. About’s
standard license texts and component now live in a deferred chunk. Total JS can
increase slightly from chunk/lifecycle code even while startup JS falls.

Backdrop regression fixtures exercise 40 instances with eight slides each:
requests are limited to the viewport margin, DOM is at most two slides per card,
and rotation timers stop on hidden-document or reduced-motion changes. A log
burst retains the latest 2,000 lines after coalescing updates. These are verified
work bounds, not measured process CPU/RSS percentages.

The native comparison uses the pre-audit local release artifact, rather than a
controlled rebuild of the old source. The final executable was built with
`cargo build --release --locked --offline --features tauri/custom-protocol --manifest-path src-tauri/Cargo.toml`;
its embedded main asset matches the final frontend build. These savings describe
the combined result, not the isolated effect of individual compiler flags.
Final main CSS is 43,547 bytes; deferred About JS/CSS are 62,728/347 bytes.
Existing icon artwork is small relative to the license payload and was preserved
without lossy recompression.
